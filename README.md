# 灵犀 · dsh-lingxi-panel

一个面板，三块数据：**进化**（闸门 / 环境事实 / 技能提名 / 疗效 / 教训）、**记忆库**（分型记录 / 词法检索 / 冲突消解 / 巩固）、**实时指标**（直接读宿主已提交的会话日志）。

**只做本地模式**：记忆库没有任何网络请求，没有云端配置项，数据不出本机。

## 写记忆：模型自己判断（tool-based）

本插件向模型注册 `lingxi_remember` 工具（schema 校验：kind / text / sharing / evidence）：

- 判断“值不值得记”交给模型，正则不再做主力；
- 合法性、隔离、去重交给本地：一律 private + candidate 落库，跨会话共享必须人 promote；
- 关键词抽取降级为 `heuristic-instruction`（置信 0.4，永不自动注入，只进待确认）。

实测：工具已出现在模型可见工具列表，真实调用返回 `已记入灵犀（preference · active · created）`。

## 常驻核心记忆（core blocks）

借鉴 Letta 的 core memory：注入块最前面**固定**放最强的 2–3 条约束/事实（`coreRecords`，默认 3），
不因为这轮问法不同而漏掉；后面才是「最近工具教训」与「按需词法召回」。
实测注入块开头即三条用户约束（置信 99% / 99% / 57%）。

## 记忆 → 模型上下文（本轮的核心）

记忆库不是摆设，它真的进入模型上下文：

- **注册方式**：每个 agent（会话）在 `agent/created` 时注册一个 scoped prompt section（`systemPrompt.section`），文本是同步缓存，不阻塞组装；插件激活时还会用 `ctx.agents.list()` 给**已在运行**的会话补注册。
- **刷新时机**：用户消息进入 inbox（`agent/inbox/claimed`）后异步刷新一次——这时才知道本轮要问什么，召回带相关性。
- **隔离**：召回走 `mayInject`，默认只注入本会话可见的记忆（`private` 只回原会话，`workspace` 同工作区，`global` 全局）；没有相关记忆时返回空块，不注入。
- **反馈**：注入后用户下一句是纠正 → 这批记忆记 `miss`；注入后工具连续成功 → 记一次 `hit`（每个会话每轮只记一次）。
- **自动捕获**：同一「工具 + 错误码 + 规范化消息」第 2 次失败，自动沉淀一条 `private` 教训（带来源会话、证据），下一次组装就会带上它。
  错误文本会先规范化（路径/数字/引号内容抹成 `<path>` `<n>` `<q>`），所以同一场景只会有一条记忆。
- **加强而非新增**：已沉淀过的失败再次出现，不新增记录，而是给同一条加证据（`refined` 计数），说明"这条记忆还不够强"。
- **面板可调**：记忆页签里可直接暂停/恢复注入、切换字符预算（400/700/1200），以及把私有记忆共享到工作区/全局、或遗忘；配置写入 `.meta.json`，重启后保持。

可核查：`~/.dsh/lingxi-memory/injection-status.json` 每 30s 落一次（配置、已注入会话数、命中、证伪、自动捕获、加强、重复失败、字数、错误）。

抽屉/浮层不会遮挡宿主窗口控制按钮（头部已下移并右侧留白）。

## 上下文抗干扰（防旧记忆劫持新任务）

- 会话隔离闸门：private 只在来源会话可见；workspace 限工作区；global 需跨会话复现或人工确认。
- **核心记忆弱相关门**：核心约束/事实不再无条件注入——与本轮任务无词法交集（CJK 2-gram 匹配）就不进上下文，从源头避免"新会话被旧项目经验干扰"。
- 注入块首行固定声明：与本轮无关就忽略；与用户当前指令冲突时，以用户当前指令为准。
- 无足够相关记忆时 abstain（不注入），不硬凑。

## 工具守卫（动作层拦截）

同一个调用（工具名 + 参数签名）刚刚原样失败过，宿主会直接拒绝这次重试，并给出换法建议：

```
刚才同一个调用失败了（FS_NOT_FOUND）。不要原样重试：先用 glob 或列目录确认目标存在，再读取。
```

- 每个签名只拦一次，换参数或换方法即放行；
- `guardDenied / guardEffective / guardIneffective` 计入进化得分，面板「闸门与纠错」卡直接显示；
- 实测：对同一路径连续两次 `read`，第二次被拦截并返回上述提示。

## 模型可用的两个工具

- `lingxi_remember`：模型判断值得长期记住时写入（schema 校验，默认 private + candidate）；
- `lingxi_recall`：按主题检索（隔离过滤；无结果时明确说没有，不编造）。

## 数据清洗与回滚

- 按 状态/类型/天数/关键词 组合筛选，先预览数量再执行**硬删除**；
- 单条记录可在详情抽屉里直接删除；
- 任何删除/重置/清洗都先写 `backup/`，面板可「从备份恢复」，恢复本身也会先备份当前库。

## 场景隔离是统计的前提（踩过的坑）

所有覆盖率/疗效都按 `tool|code` 这个"场景键"统计。曾经因为合并只看文本相似度，
`edit · FS_STALE_VERSION` 与 `write · FS_STALE_VERSION` 被当成同一条合并，
导致 meta 与正文错位、覆盖率在 3/8 与 6/8 之间反复跳动。

现在的硬约束：

- `isSameClaim()` 里，工具或错误码不同就**绝不合并**；
- 启动时修复历史错位（按 meta 重写正文）；
- 回归测试 `合并约束：不同工具的同名错误码不会被合并` 长期看住这一点。

## 覆盖率与自动补缺

- 高频场景（跨会话 ≥2、出现 ≥5 次）若没有活教训，就是缺口；
- 每次扫描最多自动补 3 条（带真实频次作为证据），补完立即重算；
- 同一场景被淘汰 3 次后停止重建，避免淘汰↔重建死循环；
- 实测：首跑覆盖 3/8 → 补缺后 8/8。

## 曝光感知的可靠度

每条记忆记录"被注入过几次"（`exposures`）。排序用：

```
reliability = (min(命中, 曝光) − 证伪) / (max(曝光, 命中+证伪) + 5)
```

命中数不能超过曝光次数，避免"被反复塞进上下文"被误当成"有用"。
单条记忆的命中只在本轮成功的工具与其主题匹配时记一次。

## 观察窗口（不提前邀功）

教训沉淀不足 1 天时，面板显示「观察中（<1 天）」，不拿 0 天窗口的 0 次当结论。
满 1 天后才显示「治理前 → 治理后」或「失败下降 x%」。

## 启发式抽规则默认关闭

关键词正则抽"规则"准确度不足（用户已明确指出），因此默认关闭。
记忆写入只保留：工具失败沉淀、模型主动 `lingxi_remember`、覆盖率补缺。
历史遗留的 `heuristic-instruction` 记录会被卫生规则隔离。

## 记忆模型（`memory/`）

分型 `constraint / preference / fact / lesson / skill / episode / strategy`；写入五态 `add / update / no-op / supersede / contradicted`；双时态 `validFrom / validTo`；凭据入库前脱敏（`⟨redacted⟩`）。

检索：BM25（字符 bigram，中文免分词）+ 置信度 / 作用域 / 使用频次，RRF 式名次融合；主题级去冗余 + 字符预算；信号太弱时 **abstain**（宁可说不知道，也不塞不相干的记忆）。

巩固：近重复合并、候选转正、休眠、退休、冲突收敛；启动时按 `consolidateHours` 周期跑一次。

## 会话隔离（硬约束）

- 每条记录带 `origin`（来源会话 / 工作区）与 `sharing`（private / workspace / global）。
- **默认 private**；记录 id 按可见性分区计算，同一句话从两个会话学到是两条记录，不会后者覆盖前者。
- 不同分区之间既不合并、也不互相消解矛盾；检索、列表、待确认统一走 `mayInject`。
- 放宽只能走 `POST /lingxi/memory/promote`（用户动作）。

## 去噪

占位/测试文案、过短、纯符号、单次低置信、陈旧未用、休眠/退休、近似重复簇 → 打 `noise.score` + 原因；默认隐藏 `≥0.5` 并折叠近似簇，显示「已折叠 N 条近似 · 已隐藏 M 条低信号」，可一键展开。只标注，不删除。

## 同轮纠错（不必等下一轮）

工具失败时，`tools/post-execute` 会把与该失败相关的记忆追加进工具结果的内容块，模型下一步就能看到：

```
【灵犀提示】这次调用命中了过往同类失败经验：
- 当「read」遇到「FS_NOT_FOUND」时：先确认参数与前置条件…
请对照上面的前置条件再决定下一步，不要直接重试。
```

- 同一轮同一失败只贴一次（避免刷屏）；下一条用户消息进来时重置。
- 记忆库里没有相关条目就完全不打扰（abstain 时不加）。
- 统计里单独计 `warned`，便于观察"同轮纠错"实际触发频率。

## 程序性记忆（学“怎么做得顺”）

只学“别犯什么错”不够，还要学“怎么做成”。借鉴 Voyager 技能库与 AWM 的轨迹归纳：

- 只记录**成功**的工具调用序列，失败立刻清空窗口（失败轨迹不算流程）；
- 窗口 5 步，且必须含 ≥2 种工具，避免单一工具连刷被当成流程；
- 模式键用「相邻工具对的无序集合」，所以 `read→glob→read` 与 `glob→read→glob` 视为同一流程，窗口滑动不会换键；
- 首次观察即写入一条 `skill` 候选（仍需在待确认队列确认才转正），之后再出现就加强证据；
- 注入时按最强相关召回，模型据此复用“先 glob 再 read”这类流程。

实测（本轮验证）：`procedures: {tracked:1, created:1}`，学到 `常用流程（5 步）：plugin_manager → glob → read → glob → read`。

## 进化：按场景各自学（UCB1）

场景按工具分类：`file`（read/write/edit/glob/grep）、`command`（pwsh/bash/terminal_*）、`web`（web_fetch/web_search）、`other`。
每个场景一个独立的 UCB1 进化器，只学自己的注入预算（读文件类默认 500、命令类 700、联网 500）：

- 每 10 分钟用该场景的「命中 − 证伪 − 2×重复失败 + 0.5×(提示有效 − 提示无效)」评估当前预算；
- 没试过的预算先探索，之后「均值 + 探索项」选下一档；
- 选择结果通过 `injector.configureScene(scene, { charBudget })` 直接生效，并写进 `.meta.json` 的 `sceneEvolution`，重启恢复。

面板「参数进化」卡下方显示各场景当前预算。

## 进化：全局参数（UCB1）

- 候选参数组：轻注入 400 / 均衡 700 / 重注入 1200 / 慢捕获（阈值 3）。
- 每 10 分钟评估一期得分：`命中 − 证伪 − 2×重复失败 + 0.5×(自动捕获 + 加强)`，归一到 0..1。
- 选择规则：没试过的臂先探索，之后「均值 + 探索项」；结果直接生效到注入预算与捕获阈值，写进 `.meta.json`，重启恢复。
- 概览「参数进化（UCB1）」卡显示当前臂、评估轮次、本期得分、各臂均值。

## 同轮纠错的有效性（有反馈）

- 提示之后工具成功、同一失败没再犯 → `warnEffective`，被提示的记忆记 `hit`；
- 提示之后同一失败再犯 → `warnIneffective`，相关记忆记 `miss`；
- 两者都进进化得分：`… + 0.5×warnEffective − 0.5×warnIneffective`，只会喊口号拦不住错的参数组会被淘汰。

## 教训文案按错误码给动作

自动捕获不再写“先确认参数与前置条件”这类正确的废话，而是按错误码给可执行动作（`lessons.js`，纯本地规则）：

| 错误码 | 动作 |
| --- | --- |
| `FS_NOT_FOUND` / `ENOENT` | 先用 glob 或列目录确认目标存在，再读取；不要反复重试同一路径 |
| `FS_STALE_VERSION` | 写之前先 read 一次当前内容，再 edit |
| `FS_NOT_OBSERVED` | 先 read 再编辑（读后写） |
| `EACCES` / `EPERM` | 检查权限与占用，必要时换可写目录 |
| `TOOL_TIMEOUT` | 缩小输入或分批执行，再重试 |
| `WEB_PROVIDER_ERROR` | 换更短更具体的检索词或换来源 |
| `SEARCH_FAILED` | 先确认搜索根目录与模式 |
| 其它 | 退回通用文案 |

## 注入有效性（关联口径）

会话结束时（`agent/disposed`）落一条质量记录到 `quality.jsonl`：是否注入了非空记忆块、工具调用数、失败数。
面板概览按「有注入 / 无注入」两组算会话工具失败率——这是**关联**，不是因果；样本少时会显示会话数，不假装结论。

## 学习效果归因（前后对照）

一条教训被沉淀之后，同类失败真的少了吗？把会话日志里的失败事件按 `tool|code` 分组，
再按记忆的写入时间切开，得到「捕获前 / 捕获后」的次数与日均速率（窗口天数会显示出来，短窗口只作参考）。

实测（首次接入，捕获后约 0.5 天）：

```
read · FS_NOT_FOUND        77 次（10.28/天） → 4 次（8/天）
web_fetch · WEB_PROVIDER_ERROR  24 → 0
edit · FS_STALE_VERSION         14 → 0
合计 115 → 4
```

读取的 4 次里有一部分是我自己为验证同轮纠错而故意制造的失败，所以这张表要等窗口拉长后再看趋势。

## 疗效与复发率（可复算，不靠感觉）

- **日粒度指标**：注入/命中/证伪/捕获/加强/重复失败按天落进 `metrics.json`，面板画近 14 天趋势，并给出「本周 vs 上周」。
- **复发率**：扫最近 40 个会话日志里 `tool/result` 的报错，按「工具 + 错误码 + 规范化消息」聚合；出现 ≥2 次的场景算一次复发。
- **高频反复场景 → 一键沉淀**：复发榜里出现 ≥5 次的场景直接列在疗效卡里，点「沉淀为记忆」写入一条全局候选教训（仍需你确认才生效）。

实测样本（首次接入时）：178 次失败 / 28 个不同场景 / 复发率 50%；榜首 `read · FS_NOT_FOUND` 77 次、`web_fetch · WEB_PROVIDER_ERROR` 24 次。
